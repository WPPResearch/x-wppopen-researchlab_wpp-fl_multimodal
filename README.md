# Multimodal Federated Learning Framework

_Requires Python: >=3.12,<3.13_

This repository contains a framework for multimodal federated learning, designed to handle and process diverse data types in a distributed manner. The federated learning simulation is powered by the [Flower (flwr)](https://flower.dev/) framework.

> 🚀 **Official Repository**
> This is the official open-source home for the Multimodal Federated Learning Framework under the [WPPOpen](https://github.com/WPPOpen/x-wppopen-researchlab_wpp-fl_multimodal) initiative. All active development, including bug fixes, feature updates, and performance improvements, takes place exclusively within this repository. 
## Project Structure

```
fl_multimodal/

```

## Data Setup

It is required to place your train and test data in a subdirectory under the `datasets` directory. This subdirectory should be named following a versioning convention (e.g. `V11`, `V12`, etc.). The `partition-dataset` script will look for your data in this location.

>
> To help you get started quickly, we have included the `Vtest` dataset (`train.json` and `test.json`) in this repository via **Git LFS**. You can use this dataset to run an initial example of the pipeline.

## Getting Started

### Prerequisites

This project uses [uv](https://docs.astral.sh/uv/) for dependency management. Make sure you have it installed on your system:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### Installation

1. Clone the repository:

   ```bash
   git clone <repository-url>
   cd fl_multimodal
   ```

2. Install the dependencies using uv:

   ```bash
   uv sync
   ```

3. Log in to Weights & Biases:

   To enable logging of metrics to Weights & Biases during the simulation, you need to log in to your W&B account. This allows the `run-simulation` script to output its metrics per FL round.

   ```bash
   uv run wandb login
   ```

4. Set Up Environment Variables:

   Create a `.env` file in the root of the project. You can use the `.env-template` file as a reference for the required variables.
   
      > **Note:** Some values in `.env-template` (such as API keys or credentials) are not included by default and need to be provided upon request. Please contact the project maintainer/administrator to obtain these values before running the scripts.

    Environment variables are loaded automatically when the scripts run, so no additional manual setup is required. This approach works seamlessly across Windows, macOS, and Linux, ensuring the scripts have consistent access to the necessary API keys and configuration settings.

The following scripts are the core components of this framework:

### 1. `partition-dataset`

This script is used to partition a dataset for a federated learning setting. It prepares the data to be distributed among multiple clients.

**To run the script:**

```bash
uv run partition-dataset VERSION [OPTIONS]
```

**Arguments:**

| Argument | Description | Default |
|---|---|---|
| `VERSION` | Subfolder under `datasets/` (e.g. `Vtest`) | **Required** |
| `--datasets_dir` | Path to the datasets directory | `./datasets` |
| `--train_file` | Name of the training file | `train.json` |
| `--test_file` | Name of the testing file | `test.json` |
| `--label_col` | Name of the label column | `label` |
| `--num_clients` | Number of clients | `10` |
| `--split` | Partitioning strategy (`homogeneous` or `heterogeneous`) | `homogeneous` |
| `--alpha` | Dirichlet alpha for heterogeneous partitioning | `1.0` |
| `--seed` | Random seed for reproducibility | `42` |

**Output Directory Structure (`data/`)**

After running the `partition-dataset` script, the `data/` directory will be generated with the following structure. This folder contains the partitioned raw data for each client and the server.

```
data/
└── <version>/
    └── <partition_case>/
        ├── client/
        │   └── raw/
        │       ├── client_0_train.json
        │       ├── client_1_train.json
        │       ├── ...
        │       ├── client_samples.json
        │       └── partition_distribution.png
        └── server/
            └── raw/
                └── server_test.json
```

-   `<version>`: The dataset version passed as a positional argument (e.g., `Vtest`).
-   `<partition_case>`: Describes the partitioning strategy (e.g., `split=homogeneous_clients=3`).
-   `client/raw/`: Contains the raw training data for each client, a JSON file with sample counts, and a PNG image showing the label distribution.
-   `server/raw/`: Contains the raw test data for the server.

### 2. `encode-dataset`

This script encodes the partitioned dataset, preparing it for the model. This may involve feature extraction or other preprocessing steps.

**To run the script:**

```bash
uv run encode-dataset VERSION [OPTIONS]
```

> 
> To run the encoding script, you must have the `zcta_embeddings.csv` file inside the `data/` directory. This file contains the PDFM embeddings from Google and is required for geographical data encoding.
> If you want to extract these embeddings, you can request access from Google as stated in their [population-dynamics codebase](https://github.com/google-research/population-dynamics).

**Arguments:**

| Argument | Description | Default |
|---|---|---|
| `VERSION` | Subfolder under `datasets/` (e.g. `Vtest`) | **Required** |
| `--num_clients` | Number of clients | `10` |
| `--split` | Partitioning strategy (`homogeneous` or `heterogeneous`) | `homogeneous` |
| `--alpha` | Dirichlet alpha for heterogeneous partitioning | `1.0` |

**Output Directory Structure (`data/`)**

The `encode-dataset` script adds an `encoded/` directory to the structure created by `partition-dataset`. This directory contains the encoded (embedded) data in Parquet format.

```
data/
└── <version>/
    └── <partition_case>/
        ├── client/
        │   ├── raw/
        │   └── encoded/
        │       ├── client_0_train_emb_pdfm_classification.parquet
        │       └── ...
        └── server/
            ├── raw/
            └── encoded/
                └── server_test_emb_pdfm_classification.parquet
```

-   `client/encoded/`: Contains the encoded training data for each client in Parquet format.
-   `server/encoded/`: Contains the encoded test data for the server in Parquet format.

### 3. `run_simulation`

This script starts the federated learning simulation. Before running this script, you must configure the `config.yaml` file to your desired specifications.

**Configuration (`config.yaml`)**

The `config.yaml` file allows you to customize various aspects of the simulation. Below is a detailed breakdown of the available parameters.

***

#### Server

| Parameter | Description |
|---|---|
| `strategy` | The federated learning strategy to use. |
| `fraction_fit` | The fraction of clients to use for training in each round. |
| `fraction_eval` | The fraction of clients to use for evaluation in each round. |
| `num_rounds` | The total number of federated learning rounds. |
| `server_dataset_included` | Whether to include a dataset on the server for evaluation. |

***

#### Client

| Parameter | Description |
|---|---|
| `num_clients` | The total number of clients to simulate. |

***

#### Model

| Parameter | Description |
|---|---|
| `name` | The name of the model to use. |
| `hidden_embed_dim` | The dimension of the hidden embedding layer. |
| `embed_dim` | The dimension of the embedding layer. |
| `hidden_dim` | The dimension of the hidden layer. |
| `dropout_prob` | The dropout probability. |
| `modality_dropout_prob` | The modality dropout probability. |
| `local_epochs` | The number of local epochs for each client. |
| `batch_size` | The batch size for local training. |
| `lr` | The learning rate for the optimizer. |
| `weight_decay` | The weight decay for the optimizer. |
| `optuna_n_trials` | The number of Optuna trials for hyperparameter optimization. |

***

#### General

| Parameter | Description |
|---|---|
| `use_wandb` | Whether to use Weights & Biases for logging. |
| `random_seed` | The random seed for reproducibility. |
| `text_embedding_task` | The task for text embedding (`classification`, `clustering`, etc.). |
| `data_version` | The version of the dataset to use. |
| `data_split` | The data partitioning strategy (`homogeneous` or `heterogeneous`). |
| `alpha` | The Dirichlet alpha for heterogeneous partitioning. |
| `one_hot_modalities` | A list of modalities to be one-hot encoded. |

***

#### Backend

| Parameter | Description                                                |
|---|------------------------------------------------------------|
| `client_resources.num_cpus` | The number of CPUs to allocate to each client.             |
| `client_resources.num_gpus` | The fraction (0 to 1.0) of GPU to allocate to each client. |

Make sure to review and edit this file before running the simulation.

**Output Directory Structure (`outputs/`)**

After running the `run_simulation` script, an `outputs/` directory will be generated with the following structure. This folder contains the trained model checkpoints, the configuration file used for the run, and the final results.

```
outputs/
└── <date>/
    └── <time>/
        ├── config.yaml
        ├── model_state_fed_acc_<accuracy>_round_<round>.pth
        ├── ...
        └── results.json
```

-   `<date>`: The date the simulation was run (e.g., `2026-03-11`).
-   `<time>`: The time the simulation was run (e.g., `14-26-47`).
-   `config.yaml`: A copy of the configuration file used for this specific run.
-   `model_state_fed_acc_...`: The trained model checkpoints, saved at different rounds with their corresponding accuracy.
-   `results.json`: A JSON file containing the final evaluation results and metrics.

**To run the script:**

```bash
uv run simulation
```

### 4. `infer-fed-model`

This script is used to perform inference using the trained federated model.

**To run the script:**

```bash
uv run infer-fed-model [OPTIONS]
```

**Arguments:**

| Argument | Description                                                                                                                        | Default |
|---|------------------------------------------------------------------------------------------------------------------------------------|---|
| `--run-folder` | Path to the specific run folder containing the model                                                                               | `None` |
| `--run-test` | Place the evaluation results to a leaderboard to inspect the performance over different runs. Requires private `.env` credentials. | `False` |
| `--allow-override` | Allows overriding existing evaluation results on the leaderboard.                                                                  | `False` |

**Output Directory Structure (`datasets/`)**

This script generates a `scoring/` directory within the corresponding dataset version folder (e.g., `datasets/Vtest/`). This directory contains the model's predictions.

```
datasets/
└── <version>/
    └── scoring/
        └── pred_<...>.csv
```

-   `scoring/`: Contains the prediction files generated by the inference script.
